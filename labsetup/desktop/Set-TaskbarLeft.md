# Taskbar alignment: Left

1. Double-click Set-TaskbarLeft.cmd as the user whose taskbar should change. No administrator rights, elevation or account substitution. No companion files or installation. Closing pause keeps output visible; /? prints help.
2. Supported: Windows 11 client (ProductType 1, build 22000 or newer), plus Windows Server 2025 Desktop Experience (ProductType 2 or 3, build 26100, registry InstallationType exactly Server). Domain controllers with Desktop Experience are included. Cumulative updates retain the base build. Server Core, older Server releases, unknown installation types and other Server base builds are refused before any write. Windows 10/earlier clients remain a no-op.
3. Writes only HKCU/Software/Microsoft/Windows/CurrentVersion/Explorer/Advanced/TaskbarAl as DWORD 0 and reads it back. Explorer may ignore or delay applying this local preference; this is not a guaranteed stable public configuration API. No other taskbar, Start or power setting changes.
4. No forced Explorer restart or sign-out. Registry readback verifies the saved value, not visible alignment. If needed, use Settings > Personalization > Taskbar > Taskbar behaviors > Taskbar alignment > Left. Restore Center in the same UI. Managed policy, alternate shells or future Windows changes may override/ignore the preference; no policy bypass is attempted.
5. Exit 0: saved/read back, older-client no-op or help. Exit 2: unsupported OS, invalid arguments or failure. Failed readback may leave the preference changed.
6. Validation: extracted support predicate tested without OS mutations; PowerShell syntax and harmless CMD help/invalid-input checks. No real TaskbarAl write or target-VM/UI test. The human reports Left is available on his Server 2025 VM; this is not evidence that this repaired script applied it.
